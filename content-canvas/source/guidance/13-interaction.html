14 / Interaction

One vocabulary of movement.

Everything that moves on a maths board is built from a closed set of behaviour tokens. Tokens compose into recipes (the moves of written working) and into components (interaction presets). Worked solutions and multi-step problems are scripts: data played by the runtime. Nothing sets its own timing, easing or distance; every value is a --cc-* token. This chapter extends 13 / Motion: the stage moves there are behaviour tokens too.

Build procedure

  1. Name the mathematical change the learner must see.
  2. If it is lines of working or a word problem, write a script (below). Otherwise choose a component by its description, useWhen and notFor; fill only its declared values.
  3. If neither covers it, compose behaviour tokens as a kit move and raise a component ask. Never invent a timing, easing or path.
  4. Call components and play scripts through the runtime; each call resolves at rest, so narration starts a move at the word that names it.
  5. Check the rules below before output.

Behaviour tokens

appear, type-in, fade-in, leave, bring-in, rest, glide, arc, converge, copy-down, make-room, hop, snap, lift, settle, return-home, scroll, physics, split-open, swap-glyph, turn-glyph, tint, role, mute, focus-frame, answer-frame, count-badge, strike, reach, draw, teeter, judge, attention, tap-hint, extract, deposit, recall, clear-working, shade-part. Each token fixes channels, duration, easing, path, sound and end state (behaviour-tokens.json). Translate, rotate and opacity only.

Scripts

A script is {key, mode, layout, steps:[{say, ops}]}. say is the status-chip line for the reader and is never drawn on the board. Each op is [recipe, ...args]. Token specs are space-separated; id=text names a token so later ops can move it.

SpecMeaning
~xtight: --cc-work-tight before it (2 ~x)
^2 · _50superscript (half size) · radicand under one bar
f=[ a / b ]fraction with id f
#A · &kma known's name (Action role) · a unit (upright, content weight)
lowercase letteran unknown: bold italic serif, as everywhere in Content Canvas

mode:"expr" (simplifying one expression) puts a hanging = before every line after the first; mode:"eq" lines carry their own relation. Recipes: newline (with from: extract or recall), down, focus, split, merge, move (with text to invert an operation mid-flight), flip, cancel, insert, remove, arcs, distribute, collect, replace, count, hop, joinFrac, addFrac, unfrac, sum, rule, tint, role, dim, box.

Multi-step problems

layout:"problem". The first step shows the statement with given quantities marked {q1:40} (Emphasis role), an optional figure whose labels are given quantities too, and the ledger: the knowns rail with one empty slot per quantity to find (A, B, C…, Action role). Then each part runs the same loop: clear the previous working → newline "#A = …" with given values flying from the statement (extract) and knowns flying from the rail (recall) → work it with recipes → box → deposit the result into its slot. The last slot is the answer. A known keeps the Action role wherever it appears; the figure part in use is shaded in Concept.

Rules

  • P01 Translate, rotate or opacity. Scale only where the scale is the mathematics: transform.dilate, and the overfull column digit in column addition.
  • P02 Tokens only: every duration, easing, distance, colour and stroke is a --cc-* token.
  • P03 Reduced motion lands on the end state at once; the end sound plays once. Physics shows at rest.
  • P04 Every call resolves a Promise at rest. P05 The application judges; components show judgement.
  • P06 One attention target. P07 Readable text never fades: history and out-of-focus text take muted.
  • P08 Sound is synthesised noise or one glide at --cc-sfx-peak, same pitch on repeats, host mute honoured; two-note rising is correct only, falling is wrong only.
  • P09 Hover is subtle and only on the visible clickable part; the cursor is an arrow except on clickable things.
  • P10 The learner makes the change (a cut, a fold, a hop, an order); the board never shows it already made. P11 A whole keeps its size.
  • P12 Each line of working is born from the line above; every number has a source (split, merge, insert/replace/newline with from, or the first line). No side labels: the motion carries the meaning.
  • P13 Equality chain: simplifying uses a hanging = on every line after the first. A named chain (#A = …) shows its name only on the first line and on the framed last line; the lines between start with = under the first = (the runtime does this in down and box). P14 Multiplication is ×, minus is −.
  • P15 Place value is unbreakable: every digit at rest is centred on its own column, including products, remainders and carries.
  • P16 Instruments are translucent, arrive from the tool dial and leave when done. P17 An instrument's guides (the compass's dotted radius) exist only while it is visible.
  • P18 Things with weight move by physics. P19 No overlaps at rest; balanced layouts; geometry labels carry a halo.
  • P20 A refused drop shakes and returns home; a drop on nothing returns unmarked. P21 A reorder is judged in place; the reveal is the last rung. P22 A branch is a choice: at most four children, two levels.
  • P23 A value found by working travels back to where it belongs (a table cell, a blank, the knowns rail).
  • P24 In a multi-step problem every given quantity used is extracted from the statement or figure, and every known used is recalled from the rail; nothing is retyped.

dimsA dimension line draws from A to B between extension lines with its value counting up at the head, then settles at the middle.length, height, depth of objects and solids; perimeter sides
angleAn arc grows from the first arm to the second with degrees counting at its tip; the value settles on the bisector; a right angle gets a square.angle size; angle types; live angle exploration (drag an arm)

tableA table fills row by row; a value is found by working, not lookup: the rule leaves the header, the row value is substituted, each line comes from the one above, and the answer returns to its cell. A missing input runs the rule backwards.function tables; input/output rules; missing values; sorting data
stepsEvery line of working is made from the line before it: tokens copy down, split, merge, cross the = and cancel; in column methods every digit sits in its place-value column.simplifying expressions; solving equations and inequalities; fraction, decimal, percent, ratio calculations; written column methods (addition with carry, long division); HCF/LCM ladder; matrix multiplication
