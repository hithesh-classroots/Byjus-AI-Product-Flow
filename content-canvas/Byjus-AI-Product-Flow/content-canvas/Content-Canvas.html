01 / The contract

One source. One way to adopt it.

The atomic files indexed by content-canvas.index.json are the authored authority. This HTML is their generated visual reference. The semantic contract, component specifications and applicable concern guidance together close board, module and migration adoption.

Closed adoption in 2.1.0: the original rules, fix proposal and third-party review are parsed into 2,514 source blocks. Every block has a stable ID, source line, disposition and domain; all 1,423 active blocks have applicability, enforcement and evidence mappings. Historical host values and proposal/review commentary are explicitly merged or out of scope. A seat may not claim conformance from appearance or component validity alone.
01

The room shows through

The document, applet root and board remain transparent. Only local content surfaces paint a fill.

02

Meaning stays consistent

One claim and one focal element per board. Referents retain their role throughout the module.

03

Depth means touch

A flat surface is read. A solid base edge identifies a button; pressing spends that edge.

Authority and boundaries

  1. The applicable atomic guidance under source/guidance/ decides what a component means and where it can appear.
  2. source/contracts/canvas-contract.json and source/components/component-specs.json define the closed machine-readable values, structures, states and prohibitions.
  3. source/assets/canvas.css, source/runtime/canvas.js, source/components/component-specs.json and source/templates/ decide exact component implementation. The embedded copies and token tables are generated from those sources.
  4. Examples demonstrate these resources. Documentation chrome has its own doc- styles and is never an applet template.

The earlier split rulebook and rendered references are retired from distribution. Their historical section numbers are retained only as migration pointers. The proposal and review are evidence, not additional law. A custom component may add domain geometry and behaviour; it must use this vocabulary and pass the same checks. If the vocabulary cannot express it, extend this system and version it before claiming exact compliance. Since 2.2.0 the vocabulary includes stage motion (13 / Motion): how a stage object moves, rests, is judged and is pointed at.

Scope: the content inside a teaching board, including embedded applets and stills. The host owns theme, navigation, progress, identity, audio preference and the lesson event API. Preserve an existing applet’s mathematics, state transitions, accessibility and integration contract during a redesign.
02 / Adoption

Start with the parts.

Build a new applet

  1. Generate the closed 2.3.0 manifest; unknown fields and values are errors.
  2. Declare the module takeaways, grade band, referent ledger and visual-model ledger before board 1.
  3. Declare each board’s kind, layout, claim, takeaway, focal point, metrics, visual and reachable states.
  4. Start from the HTML or React template and the registered components.
  5. Connect the host theme and existing runtime protocol.
  6. Resolve every applicable requirement from pending to evidenced pass or justified not-applicable.

Redesign an existing applet

  1. Generate the same manifest with mode: redesign; the migration record becomes required.
  2. Inventory every view, behavior, input, output, accessibility path and host integration before editing.
  3. Record the source colour meanings, model, layout verdict and baseline artifact.
  4. Remove decoration and map function to roles; never use nearest-colour migration.
  5. Preserve mathematics, state transitions, accessibility and host protocol; record any authorised exception.
  6. Require zero diffs on a second normalisation pass and pass all evidence and regression gates.

Use in HTML

<link rel="stylesheet" href="canvas.css?v=2.3.0">
<script src="canvas.js?v=2.3.0" defer></script>
<body class="cc-embed cc-theme" data-theme="light">
  <div class="cc-viewport">
    <section class="cc-board" data-board-kind="explore"
      data-layout="I01" data-band="upper" data-claim="…">
      <!-- Use the supplied components here. -->
    </section>
  </div>
</body>

Download HTML starter for an offline, working file with the actual font, CSS and runtime embedded. External-file builds use the CSS and JS downloads. Keep the distribution version and resource hashes in the applet record. Content-addressed asset names are equivalent to version queries. Inline assets need no fake query string; pin their containing document.

Use in React

The classes and DOM contract are identical: use className and data-* attributes. React owns its rendered state. Call mount() in an effect and return its cleanup; call setTheme() from the theme prop. Use either a DOM binding helper or React handlers on a component, never both. The React download is an integration example for your existing React toolchain.

The validator is fail-closed. An incomplete authoring decision is pending; an unknown field, invalid enum, failed rule, density breach or missing redesign record is fail. Qualitative mathematical and pedagogical judgments require written evidence. They are never inferred from CSS.

Theme integration

The host passes the resolved light or dark value to ContentCanvas.setTheme(themeRoot, theme) before first display and on each theme change. Set the iframe element’s color-scheme to that same value. CSS variables and fonts do not inherit across iframe boundaries: each frame loads this kit. A standalone preview may resolve prefers-color-scheme; an embedded applet must use the host’s choice. This kit defines no new postMessage, mute or completion protocol.

.cc-theme owns tokens. Host adapters may select theme, not replace individual palette values. Namespaced --cc-* tokens prevent collision with vendor CSS. Existing --accent and --fs-title integrations must map to the canonical classes; the old bridge is no longer a competing stylesheet.

03 / Layout & fit

A fixed board. A measured fit.

Author all CSS dimensions in the canonical 924 × 519.75 coordinate space. The fit helper scales the board uniformly into a 16:9 viewport. There is no second type scale to multiply by hand.

Structure

  • Board padding comes from .cc-board; use data-eyebrow only with an actual chip.
  • Use .cc-stack, .cc-row and .cc-split. Board-level content flows in flex/grid; only the fit root and diagram internals use absolute positioning.
  • Use one block gap across sibling blocks. Inner groups may use their smaller component gap.
  • No margins inside a board. Centre text blocks across the full column; use symmetric padding for reading measure.
  • Nothing meaningful overlaps. Fill/outline pairs, point ripples and control anatomy are intentional overlays.

Fit without shrinking the rules

  1. Check the chip-padding variant.
  2. Reserve title and actions outside the repeating list.
  3. For residual list overflow, use .cc-scroll-list and keep shadows/focus rings inside its padded area.
  4. Cut repetition or split the board.
  5. Use compact row padding if needed; never reduce the type step.

At 585 CSS pixels wide the board is approximately 329 pixels tall. Test the board container’s horizontal and vertical overflow. Do not clip content to manufacture a pass.

Screen-space touch targets

mount() measures the viewport, scales the board and expands --cc-hit-units so native controls remain at least 44 physical CSS pixels in both dimensions, or 56 for Early/Middle. Diagram hit regions need the same compensation using their SVG-to-screen transform. Never expand hit regions into a neighbour. If controls cannot fit at the supported width, simplify the layout or split the task. Read-only thumbnails may shrink; interactive applets may not claim compliance below their tested minimum width.

Fill and reading load

For ordinary content boards, the tight bounding box of authored teaching content occupies at least 55% of the usable height. Measure the union of content boxes, excluding actions, padding and empty wrapper space. Intro and section boards have a 60% ceiling; dividers 40%; feedback 50%. These four kinds have no minimum. Do not inflate type or empty panels to meet occupancy. The sample uses a consistent surface gap for its teaching blocks. Deployments must still satisfy the declared band and claim at every supported width.

Count re-read labels, options, legends and controls against the word ceiling. One continuous passage read once counts as one element instead, with a separate 30-word cap; Early has no prose passage. Grids/ticks do not count as teaching elements. The declared band ceilings supersede the old “about 40 words” rule. Content boards carry one explanatory visual or formula; structural boards may be words only.

Layout catalogue

Choose the closest entry, preserve its reading order, and implement its split using the shared layout classes. These are slot recipes, not prebuilt lesson logic. Multiple panels or two explicitly compared charts are one composed visual. A comparison’s common caption names the relationship. A model bridge shows the same quantity, a common whole and an explicit equality.

Voice-led stage layouts

A tutored applet's question is spoken, so its board needs no stem. S01 (one model), S02 (two models with a relation slot between) and S03 (the answer surface is the model's own parts, each marked data-cc-option) are the closest entries for a tutored applet's boards. On-board text names results - a count, a label - never the question. Take a stem layout only when the learner must read something to answer: a number to enter, a word to choose.

One board per applet

An applet's board is mounted once and never cut to or remounted mid-applet. Its later states are reached by stage moves (13 / Motion): objects travel, split, rest, enter and leave. When the next state needs another layout - one model becomes two, S01 becomes S02 - the objects already on screen stay and move into it, and the board declares the new layout. A second model enters with bringIn() beside the first, at the same unit size. Only objects that are part of the mathematics take part; a holding area such as a tray appears only when the tray is the mathematics.

04 / Typography

Role chooses the type.

One clear idea.

Name the destination

Explain it in a readable sentence.

Label the diagram

Use no more than three principal steps on a board. Hero and title never coexist; hero and figure never coexist. Figure and micro are mathematics-only exceptions, not additional prose sizes. A narrated statement is the sanctioned 30px content-weight step. A sentence is body or larger; Early uses title-size sentences.

Weight precedence

Content is 500; short labels and navigation are 700; the board title, numerical result and button-family labels are 800. One focal text span may also be 800 at its existing size. These explicitly named uses can coexist; the old “only one 800 element” rule is retired. Do not bold other prose. Answer choices are buttons and use the button weight, even when their label is a sentence. Titles remain neutral except for a named anchored term.

Maths remains maths

Wrap only a lowercase letter representing an unknown in <var> or SVG <tspan class="var">. It is bold italic serif wherever that unknown appears. Numerals, operators, functions, units, constants, geometry point labels and fixed coefficients remain upright Roboto. Mark the glyph, not a whole expression. Superscripts and subscripts are half the parent, never below the micro size. Formula containers stay on one line.

<span class="cc-math cc-title">
  <var>a</var><sup><var class="cc-anchor" data-role="concept">n</var></sup>
</span>

Use − × ÷ ≤ ≥ ≠ … ° ′ ″ ∠ △ ∥ ⊥ ≅ ≈ ∴ √ π ± ∈ ⊂ ⊆ ∪ ∩ ∅ →. Use a true minus, not a hyphen. Keep units outside input boxes. Stacked fractions align numerator/denominator and use a neutral fraction bar; inline prose uses 3/4. Equation stacks align equals signs; column arithmetic aligns place values with tabular numerals.

The Roboto variable font is embedded from the supplied reference; its verified weight axis supports all three required weights. No network is needed. Its declared Latin subset does not cover every mathematical script. A missing glyph must be supplied in a compatible local font subset and visually checked; a fallback glyph is not proof of exact typographic compliance. The variable family intentionally permits the original metric-compatible serif fallback stack.

05 / Colour & meaning

A role is a commitment.

Concept

The primary referent the module teaches.

Emphasis

A supporting referent used to define or contrast the concept.

Action

A result, computed outcome or live value, including a static result.

Pressability is carried by geometry, not Action blue. A control editing an exponent can be Concept violet. An unknown does not automatically become orange. Green and red mean judged correct and wrong only; completion is a neutral tick.

Resolve meaning in this order

  1. On an explicitly judged answer wrapper, use correct or wrong, with the matching icon and explanatory text.
  2. For a named referent, use its module/chapter ledger binding everywhere: symbol, word, label and diagram.
  3. For unbound content, use neutral ink. Give the board’s single focal span the relevant ledger role; do not recolour context just to create emphasis.

Canonical exponent ledger: base → ink; exponent → Concept; result → Action. The base stays ink on the distinction board too. No board-local colour reassignment. A route comparison uses distinct referent IDs if its results mean “known route outcome” and “taught route outcome”; record those identities in the ledger instead of overriding a result’s colour silently.

Identity, state and focus are separate

data-role is stable identity. data-state is one current semantic treatment. data-focal names the single teaching focus. The colour role named Emphasis is not the state named emphasis. An anchored term may remain coloured on several boards without being the focal point on each one. A judged wrapper can change outcome colour while an embedded referent retains its binding.

Use the generated ladder

Surfaces use --cc-fill; stronger surfaces --cc-fill2; meaningful strokes/primary faces --cc-base; the press ledge --cc-edge; coloured text --cc-text. Never interchange ink and fill. Text on a base-filled button uses --cc-on-base. Dark mode changes palette only, including inverted ladder stops and a bright slider thumb.

Default identity roles use violet, orange and blue. Additional categorical diagrams or flat illustrations may use teal, pink, grape, gold and azure, with explicit labels/shapes. At most four hues on a board; at least 25° separation. Reserved arcs 15-40° and 130-170° belong to wrong/correct. Gold remains legal. Do not introduce extra hues unless a new version records both-room contrast evidence.

Neutral space dominates. One focal hue has priority; secondary hues take smaller areas or quieter stops. The old 60/30/10 language is composition guidance, not an unverifiable pixel score. Colour must survive a greyscale reading: use labels, symbols, dash patterns and geometry. Alpha is permitted only for graph/interval bands and point ripples with no text inside, and for stage objects resting in place through focus() (13 / Motion), whose text is muted instead of faded; local surfaces and Venn regions are opaque.

06 / States

Ten names. No improvised treatments.

Apply one data-state per element. Use setState() to synchronise DOM state, native disabled behaviour and choice semantics. Unsupported element/state pairs throw. Reset a previous state before applying another. A correct selected answer displays correct. A disabled control displays disabled; keep a previous outcome in a separate feedback element. A finished control displays complete: its tick sits inside the control and the control is inert - setState() disables it, so a learner cannot press a finished step again. The outcome slot beside a control is for judgement only (correct, wrong).

Try pressing and keyboard-focusing the button.
Default · neutral face, solid base edge

Focus, hover, pressed, loading and failure are interaction/lifecycle conditions, not extra semantic states. :focus-visible adds a visible outline without changing the semantic state. data-tone="negative" on a surface is the explicit negative presentation alias for judged-wrong feedback; it is not a new state and never describes a negative number. Figures’ “ghost” and “shade” are structural variants, not state aliases.

One attention target per board, at the next control, whole choice group or stage object to act on, never one answer option. Its outline pulses twice (on a stage object, its stroke swells twice), stops, and respects reduced motion.

Controls, surfaces and type take no decorative glow, looping pulse, hand cursor illustration, shake, bounce, gradient, bevel, inner highlight or text shadow. Press travel is the one movement a control makes; a control's state change never moves it.

Stage objects - figures, models and art - show judgement, focus and change on the object itself, and only through the stage moves in 13 / Motion. mark() gives a stage object the correct or wrong hue with a check or cross beside it, so the state is never colour alone, and keeps a wrong mark until the question is solved. focus() rests the rest of a whole in place; hint() is the one hand illustration, and it is the learner's. A stage move - or a kit move built to the same rules - is the only way a stage object moves, fades, enters, leaves or changes place: no keyframes, opacity, filter or position of an application's own. Readable text is never faded; out of focus, it is muted.

One component API for HTML and React

type chooses a component; variant chooses its construction; values supplies content or quantities; state selects presentation. Inspect ContentCanvas.componentSpecs[type] for the allowed variants, per-variant value keys, defaults, numeric bounds and supported states. Unsupported fields, states and invalid values throw before the displayed component is replaced. Do not restyle or redraw a specimen to represent a new value.

const fraction = ContentCanvas.createComponent(host, {
  type: "fraction", variant: "bar", state: "default",
  values: { numerator: 3, denominator: 4 }
});
fraction.update({ values: { numerator: 2 } });
fraction.setState("emphasis"); // still 2/4; same partitions
fraction.getConfig();          // current variant, state and relevant values
fraction.destroy();           // dispose listeners and DOM

The exported React file also supplies CanvasComponent, an adapter to the exact same implementations. Its props are type, variant, values, state and onChange. Mount inside the same .cc-theme and fitted board as HTML components. Interactive callbacks return the new value; they do not judge answers, navigate boards or replace host lesson logic.

<CanvasComponent type="slider" variant="markers-counter"
  values={{ min: 0, max: 6, step: 1, value: n, label: "Value" }}
  state="default" onChange={setN} />

Models are SVG data components. They support updating quantities through the API; they are not automatically draggable lessons. Their selected/emphasis frame identifies the model while keeping its mathematical geometry fixed. Variants with fixed notation, such as a right-angle square, deliberately expose no quantity that could turn that notation into a different angle.

Component contracts

Slider variants: continuous with object readout; discrete with notches/object readout; discrete with notches/labels; continuous with counter; discrete with notches/counter. Labels and counter never coexist. With more than twelve intervals, omit notches and use a counter. The object itself may display the value; do not add a duplicate counter. A labelled scale has equally spaced stops. Test the min, max and every supported step, including negative and multi-digit values.

Choices: identical rest styling, shared width, parallel answer form, no option singled out by attention. Selection is a tint plus inset outline and retains the edge; outcome adds an external icon. Preserve source distractors and scoring. New options should have similar reading length and diagnostic distractors; do not add “all/none of the above”. Rotate answer position across a module.

Feedback: correct/wrong appear only after judgement - on a control in its outcome slot, on a stage object as its mark (mark(), 13 / Motion). Explain why. A wrong attempt stays visible while the learner tries again; when the correct answer is shown, it sits alongside the retained attempt. Allow retry or show the answer before ending it; where a tutor leads the feedback, the order of help before the answer is the tutor's. Text hints are secondary and expand in place, at most two in sequence, with reserved room. A control never shakes or flashes on failure; a stage object's wrong mark plays only the small wiggle mark() gives it, for the length of the feedback line.

08 / Diagrams & models

The geometry carries the lesson.

Number line

Marks carry hue. Ticks and numbers stay neutral.

Coordinate plane

Arrowheads continue. Endpoint dots stop.

Shared drawing contract

  • Describe vertices, edges and faces as data. Derive geometry, labels and hit targets from those data. Use a consistent lattice; show its grid only when students read or count it.
  • SVG viewBox may use domain units. Convert stroke, text and hit-target sizes to canonical/screen units using its actual scale; a tiny user-unit font is not automatically a failure or a pass.
  • Shape outlines use the geometry stroke; helpers, hidden and ghost edges use their named variants. Hidden 6 4, construction 2 6, ghost 4 4 are distinct.
  • Arrowheads have length 3× stroke and half-width 2× stroke. Use arrowDefs(); each marker gets a unique ID.
  • Static vertices have no dot unless named or counted. Draggable vertices keep a small visual dot with a larger compensated hit area and a keyboard equivalent.
  • Render an accurate scale and equal partitions. If a geometrical illustration must be schematic, label it “Not to scale”; this never permits a misleading data chart.
  • Each informative figure has a one-sentence description naming answer-bearing content. Decorative SVG uses aria-hidden="true".

Specific diagrams

Model recipes

Choose one model per module. Introduce its unit once and retain that unit’s size. Move concrete → representational → symbolic. A second model is allowed only for an explicit contrast or equivalence bridge. Use these recipes with the shared SVG primitives; these are domain constructions, not generic UI widgets.

Accuracy checks that CSS cannot perform

Repeated addition is a strip of groups. Repeated multiplication needs nesting, branching, area or volume: three groups of two depict 2 × 3, not 2³. Count the factors against the drawing. Every question must be answerable from the shown model. A bridge states and shows both sides of its equality. A redesign must not replace a mathematically correct source model with a prettier, incorrect one.

09 / Content, media & sequence

Keep the explanation intact.

Content primitives

  • Prose is left-aligned beyond two lines. Lists are always left-aligned, with at most five rows; objectives use three or four.
  • Tables use horizontal rules only, no zebra fill, no vertical grid; at most five columns and six rows. Compared numbers are right-aligned and tabular.
  • Local cards, formula panels and inputs all use the surface family radius. Chips, row markers and media use their own named radius tokens.
  • One callout per board. Inline label chips use the label step and optional uppercase tracking.
  • Do not add host-owned breadcrumbs, progress counts, logos, rewards or close buttons to an applet. Standalone navigation lives outside its board.

Media and illustration

  • Fix the media box and crop with object-fit:cover only when the crop preserves information. Diagrams and scans with required details use contain or a re-authored SVG.
  • Media ratios: wide 16:9, standard 4:3, square 1:1, portrait 3:4, circle 1:1 for a face/object. A comparison uses equal ratio and height.
  • Media height caps: single 200, two/three 150, four or more 120 canonical units. Caption below; no shadow or border.
  • Prefer captions outside images. If overlaid, use an opaque local surface with room-resolved ink. This replaces the contradictory scrim rules.
  • Illustration is flat primitive SVG, two tones per form, up to four board hues. No texture, gradient, lighting effect or decorative state colours. Technical solid diagrams alone use isometric projection.

Use existing approved assets for realistic objects and human figures. Preserve natural photo/skin colour; do not algorithmically recolour people through a hue ladder. The old unspecified dark skin-tone palette is retired. Flat artwork may keep natural skin fills as an asset exception, recorded in its manifest; its surrounding UI still resolves by room.

Reveal, loading and failure

Reveal frame → givens → one operation at a time → result. Reserve geometry before reveal. Support stepping back; a delay is not proof that the student read a step. The motion tokens set animation durations; minimum inter-step separation is 120ms, with actual progression owned by lesson logic. Reduced motion removes animation without revealing withheld answers or bypassing learning interactions.

Loading shows the reserved frame, then names the resource after three seconds. Failure shows an alert symbol, a plain sentence and a secondary Retry control. Keep host navigation usable. Loading/failure wrappers surround the lesson state; they do not add new semantic state names.

Module structure

Declare 3-5 takeaways and map each board claim to one. Intro: a title, subtitle and optional artefact, no in-board CTA. Objectives: three or four verb-led rows. Closing: recap known content, neutral completion ticks and one primary action only when the host needs it. Practice repeats one skill and interface; challenge may combine known skills with hints; recall introduces no new notation. Preserve the source’s host-driven timing and completion behaviour.

10 / Acceptance

Conformance requires evidence.

Use the kit to reduce opportunities for drift. It does not make invalid CSS or wrong mathematics impossible. All applicable design requirements block a new or updated build’s conformance claim.

Two separate results: the included browser probe checks a limited mechanical subset. Its result is “mechanical pass/fail”, with remaining checks listed as pending. Only a completed acceptance record may say “conformant”. Never treat a skipped or unmeasurable check as green.

Test matrix

For every board, test light and dark at 924 and 585 pixels wide (and the actual minimum host width if smaller). Check the room’s top, middle and bottom stops. Exercise default, all supported triggered states, min/max, multi-digit and negative values, long copy, keyboard, touch/pointer and reduced motion. Play every stage move the applet uses with reduced motion off and on: wrong marks persist until the question is solved, nothing inside a resting group fades twice, readable text is muted rather than faded, and a hint never rests on an answer option. A successful font load precedes measurements. Compare corresponding screenshots for theme-only colour changes and state-only intended changes.

Text must reach 4.5:1 against its actual background, including disabled values that still communicate information. This release deliberately uses that one threshold for all readable text. Meaningful graphic boundaries need 3:1; decorative gridlines are exempt. Convert CSS colours with the browser’s canvas, including OKLCH, and composite transparency against the actual background. Low-contrast decoration cannot carry the only information needed to answer.

Measure collisions among teaching objects and label bounds, excluding explicit anatomy overlaps. Browser flex/grid does not prove non-overlap. Test SVG and canvas interiors independently; frame-only evidence is insufficient. Verify behaviour, not just matching screenshots: input changes must change the model, disabled controls must be inactive, and wrong answers must remain visible.

Not run yet.

Release record



On a kit version bump, re-audit affected applets. Re-run a conversion with its recorded ledgers; the second run must produce no semantic or style changes. Keep old live journeys available while a replacement is staged. An unavailable or third-party interior is registered as an exception, never called conformant.


Ownership during migration
The user’s requested redesign authorises local source changes. Preserve a source backup and record the change. For an externally maintained applet, use an authorised, version-pinned override/config hook; do not fork it silently. A cross-origin iframe or painted canvas cannot be fixed by a parent stylesheet. Obtain source or a token hook, or record the limitation and stage a rebuild. This distributable does not modify the studio broker, runner or production fleet; those systems must consume this version and enforce the same acceptance contract.

13 / Motion
The model moves. Nothing else does.


On a teaching board the change is the lesson: a whole splits, a part is looked at while its whole stays in view, a count is made where it can be seen. Stage moves are the closed set of ways a stage object - a figure, a model, art - moves, rests, is judged and is pointed at. Controls, surfaces and type keep their state treatments and every ban in 06 / States.


Scope
  • A stage object moves, fades, enters, leaves, takes a judgement or changes place only through a move below, called from ContentCanvas, or through a kit move.
  • Moves compose: run them together. A replacement is leave() of the old object with bringIn() of the new; giving way is leave() with travel() of what closes up.
  • A motion no move covers never blocks a build: it is built once as a kit move in the journey's shared code - a function on these tokens, moving only by translate, rotate or opacity, never scaling, landing on its end state under reduced motion, resolving a Promise when it rests - and raised with a component ask so it can join this list. Application code still writes no keyframes, opacity, filters or positions of its own: it calls a move or a kit move.
  • A move translates or rotates. It never scales to highlight, and it never changes a represented value: one whole keeps its size throughout.
  • Moves set presentation only. The application owns order, judgement and scoring; a move is called after the application has judged.
  • Redesigning an existing applet replaces its motion with moves wherever a move expresses it; motion no move expresses stays only as a recorded exception (02 / Adoption), and new motion is a move or a kit move.

Wrong marks accumulate until the question is solved (clearMarks(root, {only:'wrong'})); a correct mark stays until the stage changes (clearMarks(root)). Marking an object again replaces its own mark. A control is marked through its own outcome slot; an entered answer is marked on its input.


count(units, {label, side})Each unit is boxed and numbered in turn, one --cc-beat apart; the numerals then give way to the named label.Units belong to one SVG figure. The label names the result in words.


leave(els)An object goes from the stage: it fades out from wherever it rests and is then hidden, so nothing vanishes in a cut. bringIn() brings it back.Leaving is not resting: its text goes with it. Nothing is removed from the stage any other way.


bringIn(el, {faint})A new model enters in two beats. With faint it appears faint and waits there, offered: travel() makes room beside it and hint() can point at it. bringIn(el) then brings it to full strength. From hidden without faint, it rises through faint to full in one move.No scale: the model is its full size throughout, beside the first at the same unit size.


travel(els, mutate)The objects glide from where they were to where mutate placed them.The only way a stage object changes place. Size never changes.


split(parts, {gap, axis}) / join(parts)The parts of a whole part along a cut, a gap opening between them; join closes it.Parts keep their place in the whole.


lineUp(pieces, {x, y, gap})Pieces lift out and sit edge to edge, left edges aligned, for a side-by-side comparison.Edges align on one line; pieces keep their size.


resolve(slot, glyph, {also})The relation slot takes ?, >, <, = or ≠ and teeters once; also teeters the side it favours.The glyph is the claim; it agrees with the model (visual and symbol agree every frame).


hint(target)The tap hint: the learner's finger on what to act on, looping until the first tap there. It is not a text hint or a spoken hint.One per board, and while it shows it is the board's one attention target: no element is in attention. Never on an answer option - .cc-choice, .cc-media-choice, or a stage part marked data-cc-option (on S03 the model's tappable parts are options, so the hint points at the whole model). Shown again only as the idle ladder's first, silent step; never while the tutor's own pointer shows.




Timing
--cc-enter times fades, restores, a faint entry and a leave, --cc-morph travel, splits, line-ups, teeters and coming to full strength, --cc-beat one counted unit, and --cc-hold a mark's motion when the feedback line's length is not passed. Each move resolves its Promise when it rests, so the voice can sequence the board: start a move at the word that names it. Under reduced motion every move lands on its end state at once; marks keep their hue and glyph, and the hint stands still.
